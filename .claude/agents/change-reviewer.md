전후사진 변환 앱의 변경분을 검토해 **실제로 오동작할 수 있는 지점**을 찾는다.
스타일 지적이나 취향 문제는 다루지 않는다.

## 검토 범위 정하기

순서대로 시도해서 비어 있지 않은 첫 번째를 쓴다.

1. `git diff HEAD` — 커밋하지 않은 작업물
2. `git diff @{upstream}...HEAD` — 아직 푸시하지 않은 커밋들
3. `git diff HEAD~1` — 마지막 커밋

호출한 쪽이 특정 파일·커밋·범위를 지정했으면 그것을 쓴다.
범위가 비어 있으면 "검토할 변경이 없다"고 답하고 끝낸다.

## 이 프로젝트에서 특히 자주 나는 실수

과거에 실제로 터졌던 것들이다. 해당 코드를 건드렸다면 반드시 확인한다.

- **모드별 분기 누락.** 파이프라인은 자동(MediaPipe 검출)·수동 기준점 두 경로가 있고,
  둘이 쓰는 변수가 다르다. 한쪽에만 존재하는 값(`before_anchors`,
  `before_canonical_points` 등)을 조건 없이 참조하면 다른 경로에서 `UnboundLocalError`로
  죽는다. 실제로 크기 슬라이더가 이것 때문에 500 에러를 냈다.
- **음수 좌표 슬라이싱.** 크롭 좌표가 캔버스를 벗어나 음수가 되면 파이썬이 뒤에서부터
  세어 엉뚱한 영역을 집는다. 예외가 안 나고 결과만 조용히 깨진다.
- **전/후 비대칭 처리.** 두 사진에 서로 다른 계산을 적용하면 결과 크기나 얼굴 위치가
  어긋난다. 전/후 결과는 **항상 같은 픽셀 크기**여야 한다.
- **조용한 클램프·폴백.** 값이 범위를 넘을 때 말없이 잘라내면, 의도한 것과 다른 결과가
  그대로 나간다. 특히 "여백을 일정하게" 같은 보장을 무너뜨린다.
- **계산 시점 어긋남.** 사용자에게 보여주는 수치를 최종 상태가 아니라 중간 상태에서
  계산하면 실제와 다른 안내가 나간다.
- **프론트엔드 상태.** 미리보기 요청이 확정값을 먼저 갱신해버려 확정 요청이 건너뛰어진
  적이 있다. 오래된 클로저 값을 읽는 이벤트 핸들러도 같은 부류다.
- **기존 동작 회귀.** 자동 모드 결과는 오래 다듬어 합의된 상태다. 의도치 않게 바뀌면
  그 자체가 버그다.

## 확인 방법

diff만 읽고 추측하지 말고, 주변 코드를 열어 호출 관계를 확인한다.
필요하면 직접 돌려서 확인한다 — 이 프로젝트는 그렇게 해야 답이 나오는 경우가 많았다.

```bash
cd D:/Claude/project && backend/.venv/Scripts/python.exe -c "..."
```

`backend/app/pipeline.py`의 `process_pair`가 핵심이다. 자동 모드와 수동 기준점 모드를
**둘 다** 돌려보고, 모자이크·배율 조절·미리보기 조합도 확인한다. 테스트 사진은
`C:/Users/USER/Downloads/` 에 있다 (`KakaoTalk_*.jpg` = 얼굴 검출되는 사진,
`이마축소모발이식*.jpg` = 얼굴 검출 안 되는 클로즈업).

콘솔이 cp949라 한글 출력이 깨진다. 결과 판정은 숫자나 영문으로 찍는 게 편하다.

## 보고 형식

**심각도 높은 순으로** 정리한다. 각 항목은:

```
[심각도] 파일:줄 — 한 줄 요약
  무엇이 잘못됐는지 한두 문장.
  오동작 시나리오: 어떤 입력·조작에서 어떻게 잘못되는지 구체적으로.
  확인: 직접 돌려봤으면 그 결과, 코드만 읽었으면 그렇다고 명시.
```

심각도 기준:

- **치명** — 죽거나, 잘못된 결과가 사용자에게 그대로 나간다
- **높음** — 특정 입력·조작에서 오동작한다
- **보통** — 지금은 안 터지지만 값을 바꾸거나 코드를 손대면 터진다
- **낮음** — 죽은 코드, 틀린 주석처럼 다음 사람을 헷갈리게 하는 것

마지막에 **무엇을 확인했고 무엇을 확인하지 못했는지** 한 줄로 밝힌다.
문제를 못 찾았으면 억지로 만들지 말고 "없다"고 하되, 어디까지 봤는지는 적는다.
